# 0_공통 — 수집과 전처리

세 각도가 공통으로 쓰는 출발점입니다. 원천 데이터는 저장소 루트 [`data/`](../data)에 있습니다.

## 실행 순서

| | 무엇을 | 산출물 |
|---|---|---|
| 1 | `수집/01_collect_rc_race.py` | KRA API 수집 — **서비스 키 필요** |
| 2 | `수집/02_split_by_purpose.py` | `data/processed/` 용도별 3파일 |
| 3 | `전처리/01~04` | 결측·상관 점검, EDA 보고서 |
| 4 | `전처리/05_make_versions.py` | `data/versions/` v1~v8 |
| 5 | `전처리/06~07` | 버전 가이드, train/valid/test 분리 |

1번은 API 키가 있어야 하지만, **원천 데이터가 이미 `data/race_entries.csv.gz`에 있으므로 건너뛰어도 됩니다.**

## 다만 세 축이 이걸 그대로 쓰지는 않습니다

| 축 | 전처리 |
|---|---|
| ① 변별력 1차 | 여기서 만든 v1~v8 사용 |
| ① 변별력 3차 | `data/전처리_데이터셋/v1_base/`를 기준으로 엄격한 비시장 4모델 재실행 필요 |
| ② 확률 품질 | 자체 파이프라인 — 경주 단위 분할 · 윈저라이즈 |
| ③ 수익성 | 원천에서 재시작 — 배당률 `q`를 피처로 |

**목표가 달라 전처리도 달라졌습니다.** 이유는 파트 1 보고서 3.6절에 있습니다.

`config.py`가 폴더마다 복사돼 있는데, 각 파이프라인이 독립 실행되도록 한 것이라 중복이 아니라 의도입니다.
