## 왜 이 주제인가

경마는 **대중의 예측이 실시간으로 집계되어 숫자로 공개되는** 몇 안 되는 도메인입니다. 배당률이 그 숫자입니다.

일반적인 예측 문제에서는 모델의 성능을 "정답을 얼마나 맞혔나"로만 잽니다. 그런데 경마에는 **비교 대상이 이미 존재합니다.** 수만 명이 자기 돈을 걸어 만들어낸 확률 추정치가 매 경주마다 공개되기 때문입니다.

그래서 이 프로젝트는 두 가지를 동시에 묻습니다.

1. 말·기수·조교사·훈련 데이터로 1착 확률을 얼마나 잘 예측할 수 있는가
2. 그 예측이 **배당률이라는 기준선을 넘는가**

두 번째 질문이 이 프로젝트를 다른 예측 과제와 구분 짓는 지점입니다.

### 3단계를 조금 더 자세히

시장을 따라잡으려는 시도는 세 갈래로 진행됐습니다.

| 접근 | 방법 | 결과 |
|---|---|---|
| [확률 보정](src/3_시장대조/방향실험/v1_확률보정) | Platt Scaling으로 확률값 교정 | 보정 오차 0.30 → 0.01. 다만 판별력(AUC)은 그대로 |
| [비시장 모델](src/3_시장대조/비시장모델) | 배당률을 안 쓰고 피처 수를 20~100개로 조정 | 어느 구간에서도 시장에 못 미침 |
| [시장확률 보정](src/3_시장대조/시장확률보정) | 시장 확률에 모델을 소량 섞고 온도 보정 | **확률 정확도에서 시장을 근소하게 앞섬** |

세 번째가 이 프로젝트에서 시장에 가장 가까이 간 결과입니다. 2025-12-28 ~ 2026-08-09의 635경주를 **최초 1회만** 평가했습니다.

| | Race Log Loss ↓ | Race Brier ↓ | Top-1 적중률 |
|---|---:|---:|---:|
| 시장 (M0) | 1.817348 | 0.777920 | **37.80%** |
| M2 XGBoost 후보 | **1.813446** | **0.777318** | 37.48% |

Log Loss 개선폭은 `+0.003902`이고 부트스트랩 95% 신뢰구간이 `[+0.001085, +0.006721]`로 **0을 포함하지 않습니다.** 우연으로 보기 어렵다는 뜻입니다.

다만 이걸 "시장을 이겼다"고 말하기는 어렵습니다.

- Brier 신뢰구간은 `[-0.000483, +0.001687]`로 0을 포함합니다
- **Top-1 적중률은 오히려 시장이 높습니다** (37.80% 대 37.48%)
- 최종 배당 기준으로 기대수익이 양수인 후보가 없어 베팅 정책은 `no_bet`입니다

정리하면 — **확률을 매기는 정확도는 아주 조금 나아졌지만, 어느 말이 1등인지 맞히는 능력과 돈을 벌 수 있는지는 별개**였습니다. 개선폭 0.0039는 공제율 약 20%를 넘기에는 턱없이 작습니다.

이 결과가 4단계 문헌 조사의 결론과 정확히 맞아떨어집니다. 선행 연구에서도 시장 확률에 모델을 결합하면 미세한 개선은 얻지만, 그 개선이 공제율을 넘어 수익으로 이어지는 경우는 극히 드물었습니다.

모델을 고르는 데서 그치지 않고, **어디에 걸어야 하는가**까지 갔습니다.

| 단계 | 한 일 | 결과 |

| 모델 선정 | 로지스틱·랜덤포레스트·XGBoost·LightGBM 8종 비교 | 랜덤포레스트. Lift@10% 1.72배 `[1.41, 2.02]` |

| 배당 구간 필터 | winOdds 구간별로 잘라서 ROI 측정 | **10~50배 구간 상위 10%만 베팅 → ROI +32.0%** |
| 이변마 인사이트 | 피처 비교 · K-means · 의사결정나무 | 세 유형 — 데뷔형 · 베테랑 복귀형 · 신예 깜짝형 |
| 배분 전략 | 균등 · 기대값비례 · 구간별차등 · Top-only 비교 | 균등 대비 +0~1%p. **의미 없음** |

배당 구간 필터가 이 프로젝트의 실질적 결론입니다. 부트스트랩 1,000회 중 **87.9%에서 수익**이 났고, 무작위 베팅(−26.5%) 대비 58.5%p 앞섭니다.

다만 이 수치도 조심해서 읽어야 합니다. 개선 실험 6가지 중 성공한 건 배당 구간 필터 하나뿐이고, 나머지는 ROI가 −7%에서 −15% 사이였습니다. 고배당 적중을 하나씩 빼보는 로버스트니스 검사에서도 [`robustness.csv`](reports/5_이변모델_선정/결과/robustness.csv) 5개 조건 모두 음수였습니다.

**모델의 가치는 "이 말이 이긴다"가 아니라 "이 구간의 이 말들을 주목하라"는 필터에 있습니다.**

## 문제 정의

### 예측 대상

각 출전마의 **1착 여부** (`win`). 경주당 평균 10.4두가 출전하므로 양성 비율이 약 9.6%로 불균형이 큽니다.

### 기준선 — 배당률

한국 경마는 **파리뮤추얼(pari-mutuel)** 방식입니다. 참가자들이 낸 돈을 모아 주최측 몫을 뗀 뒤 맞힌 사람끼리 나눕니다. 즉 배당률은 주최측이 매긴 가격이 아니라 **사람들이 어디에 얼마를 걸었는지의 결과**입니다.

배당률을 확률로 뒤집으면 시장이 보는 승률이 나옵니다.

```
암묵 확률 = 1 / 배당률
시장 확률 q = (1/O) / S ,   S = 경주 내 모든 말의 1/O 합
```

한 경주의 `1/배당률`을 다 더하면 1이 아니라 약 1.25가 나옵니다. 주최측이 미리 떼어간 몫 때문입니다. 이 값을 **오버라운드 S**라 부르며, 우리 데이터의 경주별 중앙값은 **1.2496** 입니다. 즉 환급률이 약 80%입니다.

### 이 프로젝트의 핵심 제약

모델은 **현재 경주의 배당·베팅금액·인기 정보를 쓰지 않습니다.** 시장과 독립적으로 예측해야 비교가 성립하기 때문입니다. 어떤 열이 여기 해당하는지는 [`docs/데이터.md`](docs/데이터.md)에 정리했습니다.

## 접근 방법

```
[KRA API 11종]
      │  collect
      ▼
[raw/ 원본 JSON]
      │  전처리 · 확장창 집계 · 누수 감사
      ▼
[race_entries.csv.gz  56,648 × 156]
      │  서울 필터 · 결측/이상치 처리 · 스케일링 8버전
      ▼
[data/전처리_데이터셋/ v1~v8]
      │  시간순 분할
      ▼
[모델 학습]  ──▶  [시장 기준선과 비교]
```

### 피처 설계 원칙

- **확장창(expanding window)** — 말·기수·조교사·마주의 누적 성적은 **직전 경주까지만** 집계합니다. 오늘 결과가 오늘의 피처에 들어가지 않게 합니다
- **경주 내 상대화** — 출주두수가 6~16으로 변하므로 절대값 대신 경주 내 z점수(`__z`)와 백분위(`__pr`)를 함께 만듭니다
- **구조적 결측 보존** — 첫 출전마에게 과거 성적이 없는 것은 결측이 아니라 정보입니다. 0으로 채우되 플래그를 남깁니다

### 모델

경주 단위로 확률의 합이 1이 되도록 맞추는 것을 원칙으로 합니다. 현재까지 비교한 계열은 다음과 같습니다.

| 계열 | 사용 모델 |
|---|---|
| 선형 | 로지스틱 회귀 |
| 트리 앙상블 | Random Forest, XGBoost, LightGBM, CatBoost |
| 랭킹 학습 (LTR) | LightGBM LambdaRank, Plackett-Luce |
| 신경망 | Deep listwise ensemble |

## 열린 질문

프로젝트를 진행하며 답을 찾고 있는 질문들입니다.

1. **평가 기준이 맞는가** — ROC-AUC로 시장과 모델을 직접 비교하는 것이 올바른 방법인가
2. **결합의 방식** — 모델 확률과 시장 확률을 함께 쓰려면 어떻게 해야 하는가. 1차 시도(두 확률을 피처로 넣어 재학습)는 성능이 오히려 떨어졌음
3. **평가 시점** — 현재는 확정 배당률로 평가하지만, 실제 판단 시점에는 그 값을 알 수 없음. 이 차이를 어떻게 다룰 것인가
4. **경마장 일반화** — 서울에서 관찰된 패턴이 부산경남에서도 재현되는가

## 시작하기

### 1. 환경 준비

```bash
git clone https://github.com/khuda-data/10th-toy-team3.git
cd 10th-toy-team3
pip install -r requirements.txt
```

Python 3.10 이상이 필요합니다. 팀원 간 결과가 달라지지 않도록 버전을 고정해 두었습니다.

### 2. 데이터 불러오기

모델에 따라 알맞은 버전을 고르면 됩니다. 파일은 gz로 압축돼 있지만 pandas가 그대로 읽습니다.

```python
import pandas as pd

VERSION = "v1_base"          # 트리 모델(RF, XGBoost, LightGBM)
# VERSION = "v2_standard"    # 로지스틱 회귀, SVM
# VERSION = "v3_minmax"      # KNN, K-means

dtypes = {"hrNo": str, "jkNo": str, "trNo": str, "owNo": str}

BASE = f"data/전처리_데이터셋/{VERSION}"

train = pd.read_csv(f"{BASE}/train.csv.gz", encoding="utf-8-sig", dtype=dtypes)
valid = pd.read_csv(f"{BASE}/valid.csv.gz", encoding="utf-8-sig", dtype=dtypes)
test  = pd.read_csv(f"{BASE}/test.csv.gz",  encoding="utf-8-sig", dtype=dtypes)

y_train = train["win"]
```

### 3. 시작 전 반드시 읽을 것

작업하기 전에 **[`docs/데이터.md`](docs/데이터.md)의 「쓸 때 지킬 것」 절**을 읽어주세요. 다음 다섯 가지를 놓치면 결과가 조용히 틀립니다.

| | 지킬 것 |
|---|---|
| 1 | `hrNo` 등 식별자는 **문자열로** 읽습니다. 숫자로 읽으면 앞자리 0이 날아가 조인이 깨집니다 |
| 2 | **결과·사후 정보를 피처에 넣지 않습니다.** 해당 열 목록은 데이터 문서에 있습니다 |
| 3 | **현재 경주의 배당·베팅 정보를 피처에 넣지 않습니다.** 이 프로젝트의 핵심 제약입니다 |
| 4 | 시간순 분할을 지킵니다. `train_test_split`으로 섞으면 안 됩니다 |
| 5 | `class_weight`나 오버샘플링을 쓰지 않습니다. 확률 자체가 분석 대상이라 건드리면 보정이 무너집니다 |
