# 10th-toy-team3

**배당률이라는 "대중의 집단 예측"을 데이터 모델이 넘어설 수 있는가**

KHUDA 10기 토이프로젝트 3조입니다. 한국마사회 서울 경주 데이터로 승률 예측 모델을 만들고, 배당률에서 환산한 시장 확률과 정면으로 비교했습니다.

경마는 **대중의 예측이 실시간으로 집계되어 숫자로 공개되는** 드문 분야입니다. 보통의 예측 문제는 "정답을 얼마나 맞혔나"만 재지만, 여기에는 수만 명이 자기 돈을 걸어 만든 확률 추정치가 매 경주마다 이미 존재합니다. 그래서 질문이 하나 더 생깁니다 — **그 기준선을 넘을 수 있는가.**

> 마지막 갱신 2026-08-23 · 7단계까지 코드와 보고서 정리 완료

---

## 한 줄 결론

시장을 정면으로 이기는 데는 실패했습니다. 대신 **시장이 구조적으로 약한 구간만 골라내는 필터**로 방향을 틀어 의미 있는 결과를 얻었습니다.

## 핵심 결과 셋

### 시장은 생각보다 훨씬 정확합니다

배당률만으로 ROC-AUC 0.817이 나옵니다. 우리가 만든 어떤 모델도 이 선을 넘지 못했습니다.

| | ROC-AUC |
|---|---:|
| 시장 (배당률) | **0.817** |
| RandomForest | 0.7495 |
| 2단계 결합 모델 | 0.7081 |

피처를 20개로 줄여도, 100개로 늘려도 마찬가지였습니다. **피처 개수의 문제가 아니었습니다.**

### 확률 정확도로는 아주 조금 앞섰습니다

시장 확률에 모델을 소량 섞고 온도 보정을 하면 확률 예측 정확도가 미세하게 개선됩니다. 2025-12-28 ~ 2026-08-09의 635경주를 **최초 1회만** 평가했습니다.

| | Race Log Loss ↓ | Top-1 적중률 |
|---|---:|---:|
| 시장 (M0) | 1.817348 | **37.80%** |
| M2 XGBoost 후보 | **1.813446** | 37.48% |

개선폭 `+0.003902`, 부트스트랩 95% 신뢰구간 `[+0.001085, +0.006721]`로 **0을 포함하지 않습니다.** 다만 Top-1 적중률은 오히려 시장이 높고, 기대수익이 양수인 후보가 없어 베팅 정책은 `no_bet`입니다. 개선폭 0.0039는 공제율 약 20%를 넘기에 턱없이 작습니다.

### 이변 구간에서는 의미 있는 결과가 나왔습니다

"이 말이 이긴다"를 맞히는 대신 **"시장이 과소평가한 복병"을 골라내는** 문제로 바꿨습니다.

| | |
|---|---|
| 선별력 | Lift@10% **1.72배** `[1.41, 2.02]` — 상위 10%의 적중률이 전체 평균의 1.7배 |
| 전략 | winOdds **10~50배 구간**에서 모델 상위 10%만 단승 |
| 수익 | ROI **+32.0%** · 부트스트랩 1,000회 중 **87.9%에서 수익** |
| 이변마 유형 | 데뷔형 · 베테랑 복귀형 · 신예 깜짝형 |

**모델의 가치는 예측이 아니라 필터에 있습니다.** 다만 개선 실험 6가지 중 성공한 건 배당 구간 필터 하나뿐이었고 나머지는 ROI −7~−15%였습니다. 실전 판단의 근거로 쓰기엔 아직 표본이 부족합니다.

## 예측 모델의 범위

이 저장소가 후보로 다루는 예측 모델은 **트리 계열 넷**입니다 — Random Forest · XGBoost ·
LightGBM · CatBoost. 3차 모델링에서 함께 만들었던 두 모델은 후보에서 뺐습니다.

| 제외 | 계열 | 원래 성적 |
|---|---|---|
| Deep listwise ensemble | 딥러닝 | test ROC-AUC 0.7710 (전체 1위) · 상위 10% ROI **−8.6%** |
| Plackett-Luce hybrid | 순위학습 | test ROC-AUC 0.7684 (전체 2위) · 상위 10% ROI +23.3% |

**변별력 1위가 수익 최하위였다**는 사실 자체는 남길 만합니다. 이 프로젝트가 되풀이해 만난
"ROC-AUC 순위와 수익 순위는 어긋난다"는 관찰의 가장 뚜렷한 사례이기 때문입니다.

제외 범위와 다시 계산한 지표는 [`reports/3_시장대조/04_3차모델링_모델비교`](reports/3_시장대조/04_3차모델링_모델비교)에
정리해 뒀습니다. 원본 6종 수치는 `main` 브랜치와 커밋 `7f90843` 에 그대로 있습니다.

`○` 표시는 **저장소에 담지 않는 폴더**입니다. 원본과 코드가 있으면 그대로 다시 만들어지고,
매 실행마다 내용이 바뀌기 때문입니다. 각 폴더의 `README.md` 에 무엇이 들어갈 자리이고
어떤 명령으로 채우는지 적어 뒀습니다.

### 파일 이름 규칙

| | |
|---|---|
| `src/` 스크립트 | `01_` 부터 **폴더 안에서의 실행 순서**. 폴더가 바뀌면 다시 01부터 |
| `config.py` · `kra_client.py` | 실행하는 파일이 아니라 불러 쓰는 모듈이라 번호를 붙이지 않았습니다 |
| `reports/` 문서 | `01_` 부터 **읽는 순서**. `.docx`와 `.pdf`가 같은 이름으로 짝을 이룹니다 |
| 결과 `.csv` · `.png` | 코드가 이 이름 그대로 읽고 써서 **영문 원본을 유지**했습니다. 뜻은 각 폴더 `README.md`의 표에 있습니다 |

`config.py`는 7개 폴더에 같은 내용으로 복사돼 있습니다. 각 파이프라인이 다른 폴더에 의존하지 않고
혼자 돌아가도록 한 것이라 중복이 아니라 의도입니다.

각 `src/`·`reports/` 하위 폴더에 무엇이 들어 있고 어떤 순서로 실행하는지 적은 `README.md`가 있습니다.

## 시작하기

```bash
git clone https://github.com/khuda-data/10th-toy-team3.git
cd 10th-toy-team3
pip install -r requirements.txt
```

```python
import pandas as pd

VERSION = "v1_base"          # 트리 모델 (RF · XGBoost · LightGBM)
# VERSION = "v2_standard"    # 로지스틱 회귀 · SVM

BASE = f"data/전처리_데이터셋/{VERSION}"
dtypes = {"hrNo": str, "jkNo": str, "trNo": str, "owNo": str}

train = pd.read_csv(f"{BASE}/train.csv.gz", encoding="utf-8-sig", dtype=dtypes)
valid = pd.read_csv(f"{BASE}/valid.csv.gz", encoding="utf-8-sig", dtype=dtypes)
test  = pd.read_csv(f"{BASE}/test.csv.gz",  encoding="utf-8-sig", dtype=dtypes)
```

### 시작 전에 꼭 읽을 것

[`docs/데이터.md`](docs/데이터.md)의 「쓸 때 지킬 것」 절입니다. 아래 다섯 가지를 놓치면 결과가 **조용히** 틀립니다.

| | |
|---|---|
| 1 | `hrNo` 등 식별자는 **문자열로** 읽기. 숫자로 읽으면 앞자리 0이 날아가 조인이 깨집니다 |
| 2 | 경주 **결과·사후 정보**를 피처에 넣지 않기 |
| 3 | 현재 경주의 **배당·베팅 정보**를 피처에 넣지 않기. 이 프로젝트의 핵심 제약입니다 |
| 4 | **시간순 분할** 지키기. `train_test_split`으로 섞으면 안 됩니다 |
| 5 | `class_weight`·오버샘플링 쓰지 않기. 확률 자체가 분석 대상이라 보정이 무너집니다 |
