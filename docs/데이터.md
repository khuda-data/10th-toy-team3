### 9. 시장 정보 — 21개 (● 7 / ○ 14) ⚠️

배당률과 발매금액에서 나온 값입니다. **독립 모델의 피처로 쓰면 안 됩니다.** 시장과 비교하는 것이 이 프로젝트의 목적이기 때문입니다.

| 열 | 설명 |
|---|---|
| ○ `winOdds` `plcOdds` | 단승 · 연승 확정 배당률 |
| ○ `q` `p_raw` | 단승 시장 확률 (경주 내 합 = 1) |
| ○ `logit_q` `log_q` | `q`의 로짓 · 로그 변환 |
| ○ `pop_rank` `pop_pct` `is_fav` | 인기 순위 · 백분위 · 1인기 여부 |
| ○ `book_sum` `takeout` | 경주별 `Σ(1/배당)` · 공제율 (검산용) |
| ○ `pl_harville` `pl_disc` `q_plc` | 입상확률 관련 파생 (별도 분석용) |
| ● `winAmt` `plcAmt` `totalAmt` | 승식별 발매금액 |
| ● `log_winAmt` `liq_per_horse` | 발매금액 로그 · 두당 유동성 |
| ● `gap_h` `gap_d` | 시장 파생 지표 |

> ⚠️ **전처리 데이터셋에도 시장 파생 열 7개가 남아 있습니다.**
> 배당률 자체(`winOdds`, `q`)는 제거됐지만 위 ● 표시 열은 남아 있으므로, `df.drop(columns=['win'])` 식으로 피처를 만들면 의도치 않게 포함됩니다. **명시적으로 제외해야 합니다.**

> `winAmt` `plcAmt` `totalAmt`는 **경주 단위 상수**입니다. 한 경주 안에서 모든 말이 같은 값을 가지므로 경주 내 판별에는 기여하지 않습니다.

**시장 기준선을 계산하려면** `race_entries.csv.gz`에서 `winOdds`를 `entry_id` 기준으로 붙이면 됩니다.

```python
mkt = pd.read_csv("race_entries.csv.gz", usecols=["entry_id", "winOdds"])
test = test.merge(mkt, on="entry_id", how="left")
test = test[test.winOdds < 999]                       # 999.9는 결측 표시값
ip = 1 / test.winOdds
test["q"] = ip / test.groupby("race_id")["winOdds"].transform(lambda s: (1/s).sum())
```

### 10. 결과·라벨 — 9개 (● 1 / ○ 8) ⚠️

경주가 끝나야 알 수 있는 값입니다.

| 열 | 설명 |
|---|---|
| ● `win` | **1착 여부 — 예측 대상** |
| ○ `ord` `fin_rank` `fin_pct` | 착순 · 착순 순위 · 착순 백분위 |
| ○ `place` | 입상 여부 |
| ○ `resid` | 착순 백분위 − 인기 백분위 |
| ○ `upset` `upset_A` `upset_B` | 이변 지표 |

**이변의 두 유형**

| 열 | 정의 |
|---|---|
| `upset_A` | 인기 상위 25%인데 착순 하위 50% — "인기마의 부진" |
| `upset_B` | 인기 하위 50%인데 1착 — "비인기마의 반란" |

서로 반대 현상이므로 **합쳐서 학습하면 상쇄됩니다.** 각각 해당 부분집합에서만 정의됩니다.

> 전처리 데이터셋에는 `win`만 있습니다. 나머지 결과 열을 쓰려면 `race_entries.csv.gz`에서 붙여야 하며, **피처가 아니라 분석 대상으로만** 쓰세요.

### 11. 기타 — 1개

| 열 | 설명 |
|---|---|
| ● `fold` | train / valid / test 구분 |

## 전처리 8버전

같은 데이터를 8가지 방식으로 전처리했습니다. **이상치 포함/제거 × 스케일링 4종**입니다.

| 폴더 | 이상치 | 스케일링 | 추천 모델 |
|---|---|---|---|
| `v1_base` | 포함 | 없음 | **RF, XGBoost, LightGBM, CatBoost** |
| `v2_standard` | 포함 | StandardScaler | 로지스틱 회귀, SVM |
| `v3_minmax` | 포함 | MinMaxScaler | KNN, K-means |
| `v4_robust` | 포함 | RobustScaler | 이상치에 강건해야 할 때 |
| `v5_base_no_outlier` | 제거 | 없음 | 참고용 |
| `v6_standard_no_outlier` | 제거 | StandardScaler | 참고용 |
| `v7_minmax_no_outlier` | 제거 | MinMaxScaler | 참고용 |
| `v8_robust_no_outlier` | 제거 | RobustScaler | 참고용 |

### 공통 처리

| 단계 | 내용 |
|---|---|
| 구조적 결측 | 0으로 채우고 플래그 유지 (예: `rating` → 0, `rating_na=True`) |
| 무작위 결측 | **train의 중앙값**으로 대치. valid/test에도 같은 값 적용 |
| 다중공선성 | 상관계수 0.8 이상 쌍에서 하나 제거 (156열 → 111열) |
| 스케일링 | **train으로 fit**하고 valid/test에는 transform만 |

모든 기준을 train에서만 정한 이유는 valid/test 정보가 전처리 단계로 새어 들어가는 것을 막기 위해서입니다.

### ⚠️ v5~v8은 표본이 너무 작습니다

이상치 제거(IQR 기준)를 적용하면 행이 극단적으로 줄어듭니다.

| 구분 | train | valid | test |
|---|---:|---:|---:|
| v1~v4 | 19,637 | 6,591 | 6,660 |
| **v5~v8** | **3,772** | **315** | **89** |

**test가 89행입니다.** 경주로 치면 10개 남짓이고 1착 사례는 10건 미만입니다. 이 버전으로 낸 성능 수치는 우연에 크게 좌우되므로 **모델 선택의 근거로 쓸 수 없습니다.** 이상치의 영향을 보는 참고용으로만 쓰세요.

### 결측 상위 열 (전처리 전 기준)

| 열 | 결측률 | 원인 |
|---|---:|---|

## 쓸 때 지킬 것

### ① 식별자는 문자열로 읽습니다

```python
dtypes = {"hrNo": str, "jkNo": str, "trNo": str, "owNo": str}
train = pd.read_csv("data/전처리_데이터셋/v1_base/train.csv", encoding="utf-8-sig", dtype=dtypes)
```

`hrNo`는 7자리인데 **98%가 0으로 시작합니다.** 숫자로 읽으면 앞자리 0이 사라져서 조인이 전부 깨집니다.

### ② 피처에서 제외할 열을 명시적으로 지정합니다

전처리 데이터셋(111열) 기준입니다.

```python
ID      = ["race_id", "entry_id", "hrNo", "jkNo", "trNo", "owNo",
           "hrName", "jkName", "trName", "owName", "rcName", "name",
           "rcDate", "rcNo", "meet", "meet_cd"]
MARKET  = ["winAmt", "plcAmt", "totalAmt", "log_winAmt", "liq_per_horse",
           "gap_h", "gap_d"]
TARGET  = ["win"]
SPLIT   = ["fold"]

X = train.drop(columns=ID + MARKET + TARGET + SPLIT)
y = train["win"]
```

**`MARKET` 목록을 빼먹지 마세요.** 전처리 데이터셋에 시장 파생 열 7개가 남아 있어서, 그냥 `drop(columns=['win'])`만 하면 자동으로 포함됩니다.

`race_entries.csv.gz`를 직접 쓴다면 여기에 `winOdds` `plcOdds` `q` `p_raw` `logit_q` `log_q` `pop_rank` `pop_pct` `is_fav` `book_sum` `takeout` `pl_harville` `pl_disc` `q_plc`와 결과 열 `ord` `fin_rank` `fin_pct` `place` `resid` `upset*`도 함께 빼야 합니다.

### ③ 시간순 분할을 지킵니다

`fold` 열을 무시하고 섞으면 미래로 과거를 예측하게 됩니다. 교차검증을 한다면 `KFold` 대신 `TimeSeriesSplit`이나 `race_id` 기준 `GroupKFold`를 쓰세요.

같은 경주의 말들은 반드시 같은 fold에 있어야 합니다. 나뉘면 그 경주의 정보가 학습과 검증에 동시에 들어갑니다.

### ④ 클래스 불균형을 인위적으로 건드리지 않습니다

`class_weight="balanced"`나 SMOTE 같은 오버샘플링은 쓰지 않습니다. 이 프로젝트는 **확률 자체가 분석 대상**이라 표본 비율을 바꾸면 확률 보정이 무너집니다.

불균형이 문제라면 임계값 조정이나 확률 보정(Platt Scaling, Isotonic)으로 다루세요.

### ⑤ 경주 내 확률 합을 1로 맞춥니다

한 경주에 1착은 정확히 한 마리입니다. 말 단위로 독립 예측한 뒤에는 경주 내에서 정규화해 주세요.

```python
p = model.predict_proba(X_test)[:, 1]
test["p_raw"] = p
test["p"] = test["p_raw"] / test.groupby("race_id")["p_raw"].transform("sum")
```

### ⑥ `rating` 결측은 구조적입니다

국6등급은 레이팅을 아예 부여하지 않습니다(전체의 약 26%). 평균으로 채우면 "레이팅이 중간인 말"로 둔갑합니다. `rating_na` 플래그로 구분하세요.

### ⑦ 배당률의 999.9는 결측 표시값입니다

`race_entries.csv.gz`의 `winOdds`에 `999.9`가 들어 있는 행이 있습니다. 실제 배당이 아니라 값을 받지 못했다는 뜻이므로 시장 확률을 계산할 때 반드시 걸러야 합니다. 한 행만 남아도 평균이 크게 흔들립니다.
