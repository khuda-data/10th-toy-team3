Git 데이터셋 vs 현재 v11 전처리 품질

상관 중복 · 문자열 수치화 · 표준화 · 결측/무한값 · 경주 보존을 같은 기준으로 직접 감사

최종 판정

현재 사용 중인 revised_v11 서울+부경 모델 행렬이 더 잘 전처리돼 있다. Git의 canonical 파이프라인도 문자열 인코딩·결측 대치·모델별 스케일링을 학습구간에서 수행하지만, 상관 중복 제거가 구현돼 있지 않고 저장된 canonical 파일 자체는 아직 문자열과 결측을 가진 interim 자료다. Git의 v1~v8은 과거 재현 전용이며 v5~v8은 경주 일부 행 삭제로 사용 금지다.

1. 비교 기준

  • 상관 중복: train에서 |Pearson r|≥0.95 및 거의 완전상관을 계산했다.
  • 수치화: 실제 모델 입력에 문자열 dtype이 남는지 확인했다.
  • 표준화: 연속형 train 열의 평균 0·표준편차 1 여부와 변환 적합 범위를 확인했다.
  • 결측: 모델 입력의 NaN·±∞를 전수 계산했다.
  • 경주 무결성: 일부 말만 행 삭제하는지, 시간순·경주 단위가 보존되는지 확인했다.

3. 상관관계 세부

Git train 상위 관계: chaksun1↔chaksun2 (1.000), buga1↔buga2 (1.000), buga1↔buga3 (1.000). 현재 v11 상위 잔존 관계: jk_winrate__z↔jk_winrate__pr (0.938), rating↔hr_prev_rating (0.928), jk_winrate↔te_jkName (0.912). v11은 train에서만 상관판정을 적합해 16쌍을 제거하고 |r|≥0.95 잔존쌍을 0으로 만들었다. 이 결과는 manifest 기록뿐 아니라 저장 train 행렬을 다시 읽어 독립 계산했다.

문자열 열이 남아 있다는 사실만으로 전처리 실패라고 할 수는 없지만, 이 파일들은 별도 인코더 없이 직접 학습할 수 있는 완성 수치 행렬은 아니다. 특히 v5~v8은 이상치가 있는 말의 행만 제거해 같은 경주의 출전마 집합을 훼손하므로 현재 목적에 사용할 수 없다.

5. 중요한 공정성 제한

Git canonical은 “원천 interim + 학습 시 transformer”, v11은 “이미 변환된 행렬”이다. 따라서 파일 외형만 비교하지 않고 Git transformer를 실제 train에 적합해 OHE·대치·표준화 후 NaN/∞가 0인지 확인했다. 반대로 v11의 7개 test 경주는 착순 타깃이 0/NaN이라 경주 전체가 순위 평가에서 제외된다. 이는 피처 결측 문제는 아니지만 데이터 품질 제한으로 유지한다.

6. 결론과 권고

  1. 현재 학습에는 revised_v11_seoul_bugyeong_rank_clean_preprocessed를 유지한다.
  2. Git에서는 dataset policy·feature registry·fail-closed 테스트 구조만 선별 이식한다.
  3. Git canonical의 112개 피처를 재사용하려면 train-only 상관 pruning과 OHE 기준범주 제거를 추가한다.
  4. v5~v8은 절대 신규 모델 입력으로 복귀시키지 않는다.
