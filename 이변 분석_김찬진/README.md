# 이변 분석 자료 정리

> 2026-08-22 기준. 이 문서는 현재 저장소에 흩어져 있는 이변 관련 자료의 역할과 정의를 한곳에 모으고, 서로 맞지 않는 부분을 표시한 작업 가이드다.

## 1. 메인 주제

이 프로젝트의 메인 질문은 **경마 시장이 놓친 말은 어떤 말이며, 이변은 어떤 조건에서 발생하는가**다.

이변은 방향이 반대인 두 유형으로 나누어 다룬다.

- **다크호스(Darkhorse)**: 인기는 낮았지만 실제 성적은 좋았던 말
- **인기마 붕괴(Favorite Bust)**: 인기는 높았지만 실제 성적은 나빠진 말

두 유형은 특징의 방향이 반대이므로 하나의 이진 타깃으로 합치기보다 각각 분석한다.

- 다크호스 Core 주 모델: Random Forest 600 trees (`max_depth=8`, `min_samples_leaf=30`, `max_features=sqrt`)
- 잠금 test: ROC-AUC 0.647, PR-AUC 0.213
- 모델 점수 상위 10%: 입상률 24.7%, 전체 13.5% 대비 Lift 1.82

- 결론: 이변 후보 선별력은 재현됐으나 양의 수익률은 아직 통계적으로 확정할 수 없음

## 3. 현재 사용 중인 이변 정의

### 3.1 노트북·PDF의 정의: 인기-성적 격차 상위 5%

```text
surprise_score = pop_pct - fin_pct
threshold = quantile(abs(surprise_score), 0.95) = 0.6667
darkhorse = surprise_score >= threshold
favorite_bust = surprise_score <= -threshold
upset = abs(surprise_score) >= threshold
```

전체 56,648건 중 다크호스는 1,282건, 인기마 붕괴는 1,703건, 합계는 2,985건이다.

### 3.2 데이터 문서의 정의

- `upset_A`: 인기 상위 25%이지만 착순 하위 50%(인기마 부진)
- `upset_B`: 인기 하위 50%이지만 1착(비인기마의 반란)

### 3.3 `v3_report.html`의 정의

`upset_B`를 **인기 하위 50% 비인기마의 1착**으로 설명하고, 이 타깃의 RF 모델 성능과 예측 점수 구간별 적중률을 제시한다.

- RF ROC-AUC: 0.6422
- 전체 평균 적중률: 13.2%
- 모델 점수 상위 10% 적중률: 23.8%
- Lift: 1.81배
- 상위 10% 그룹 평균 배당: 24.5배

## 5. 이변 예측 모델 선정 보고서 분석

### 5.1 보고서가 선택한 방안

보고서는 서울 경마 32,888행을 시간순 6:2:2로 나누고, 이변이 정의되는 부분집합만으로 다음 모델을 비교했다.

- 다크호스: `pop_pct >= 0.50` 3,528행, `upset_B` = 478건, 기저율 13.55%
- 인기마 붕괴: `pop_pct <= 0.25` 1,902행, `upset_A` = 484건, 기저율 25.45%
- 비교: 로지스틱 회귀, 랜덤포레스트, XGBoost, LightGBM, 무작위 기준선
- 최종 권장: RandomForestClassifier 600그루, `min_samples_leaf=50`, 불균형 처리 없음
- 주 평가 지표: Lift@10%; PR-AUC는 보조, ROC-AUC는 참고

| 타깃 | 권장 모델 | ROC-AUC | PR-AUC | Lift@10% | 95% CI |
|---|---|---:|---:|---:|---:|
| 다크호스 | RF, depth 12 | 0.6420 | 0.2093 | 1.72 | [1.41, 2.02] |
| 인기마 붕괴 | RF, depth 8 | 0.5768 | 0.3177 | 1.47 | [1.21, 1.75] |

### 5.2 보고서의 강점

- `upset_B`가 “비인기마의 1착”이 아니라 **비인기마의 입상**임을 실제 데이터로 역산했다. 원본 데이터와 대조한 결과 `upset_B = (pop_pct >= 0.50) & (place = 1)`이 100% 일치한다.
- 입상 타깃에 단승 `winOdds`가 아닌 연승 `plcOdds`를 사용해 `v3_report.html`의 수익 해석 오류를 바로잡았다.
- 표면 ROI +65.3%가 260.3배 적중 1건에 의존하며, 그 한 건을 빼면 -8.4%로 뒤집힌다는 민감도 분석을 포함한다.
- 전체 데이터로 `upset_B`를 학습하면 인기마를 0으로 구분하는 쉬운 문제로 바뀌므로, 비인기마 부분집합에서만 조건부 확률을 학습해야 한다는 점을 명확히 설명한다.
- 선별력은 있지만 수익성은 입증되지 않았다는 결론이 적절하다.

### 5.3 보완해야 할 부분

#### P0. 제시된 코드는 그대로 실행되지 않음

10.2절의 코드는 문자열 범주형 열과 결측치 처리를 포함하지 않는다. `v1_base`에는 `ageCond`, `budam`, `meet`, `track`, `weather` 등의 문자열 열이 남아 있어 `RandomForestClassifier.fit()`에 바로 넣으면 변환 오류가 난다. 실제 실험에 사용한 인코딩, 결측치 대체, 열 정렬 코드를 포함한 완전한 pipeline이 필요하다.

#### P0. 식별자 처리 검증

보고서는 `race_id`, `entry_id`, 이름 계열을 제거했지만 `hrNo`, `jkNo`, `trNo`, `owNo`는 제거 목록에 없다. 인기마 붕괴 모델의 상위 중요 변수에 `hrNo`가 실제로 포함됐다. 이 번호를 숫자 연속형으로 사용하면 크기 순서에 의미가 있다는 가짜 분할이 생길 수 있다. 식별자를 제거한 재실험을 기본으로 하고, 유지할 경우에는 범주형 인코딩과 미지 객체 처리 규칙을 명시해야 한다.

#### P1. 모델 선정 지표가 일관되지 않음

보고서는 Lift@10%를 주 지표로 삼으면서 RF 깊이는 valid ROC-AUC로 골랐다. test에서 depth 4의 Lift@10%는 1.87, 최종 depth 12는 1.72다. test를 보고 depth 4로 바꾸면 안 되지만, 다음 실험에서는 **고정한 valid Lift@10%**로 모델을 선정한 후 test를 한 번만 평가해야 한다. “ROC-AUC를 버리라”는 표현도 너무 강하며, Lift를 주 지표로 두되 PR-AUC·ROC-AUC를 보조 지표로 함께 유지하는 편이 맞다.

#### P1. RF 우위의 통계적 검증이 부족함

제시된 신뢰구간은 각 모델의 Lift가 1보다 높은지를 보여주지만, RF가 로지스틱·XGBoost보다 유의하게 나은지는 보여주지 않는다. 특히 인기마 붕괴에서는 XGBoost의 ROC-AUC·PR-AUC가 RF보다 높고 Lift 차이는 작다. 경주 단위 paired bootstrap 또는 복수 시간 구간 검증으로 모델 간 차이를 직접 검증해야 한다.

#### P1. 불균형 처리 비교 수치의 설명 필요

메인 표의 XGBoost ROC-AUC는 0.6205지만, 불균형 처리 표의 “처리 없음”은 0.5293이다. RF도 0.6420과 0.6381로 다르다. 설정·피처·학습 범위가 다른 별도 실험이라면 표에 그 차이를 명시해야 한다. 그렇지 않다면 수치를 재산출해야 한다. 또한 본문은 SMOTE를 언급하지만 표에는 class weight 비교만 보이므로, SMOTE 결과를 분리해 제시해야 한다.

#### P1. 실전 평가 단위 보강

- 부트스트랩은 마필 행이 아니라 `race_id` 단위로 복원추출해 같은 경주 내 상관을 보존해야 한다.
- test 전체의 상위 k%를 전역으로 고르면 한 경주에 여러 말이 모이고 경주 간 점수 스케일 차이가 개입할 수 있다. 경주별 상위 1마리 또는 경주 내 상위 p%처럼 실제 베팅에 고정할 수 있는 규칙도 함께 평가해야 한다.
- ROI는 현재처럼 고배당 제거 민감도와 신뢰구간을 유지하되, 최종 모델 선택 지표가 아닌 후행 지표로 두어야 한다.

## 6. 필수 정리 사항

### P0. 이변 정의를 하나로 고정

노트북·PDF의 상위 5% 격차 정의와 `docs/데이터.md`·`v3_report.html`의 규칙 기반 정의가 다르다. 주 분석 정의를 먼저 확정한 뒤 라벨, 문서, 모델 보고서를 모두 같은 정의로 재생성해야 한다.

권장안은 다음과 같다.

- 특징 분석: 연속형 `surprise_score`와 극단 5% 두 유형을 사용
- 예측 모델: 사전에 명확히 판정할 수 있는 임계값 기반 타깃을 사용
- 성과 보고: 유형별 성능과 전체 이변 성능을 구분

### P0. `upset_B` 라벨과 문서 정의 검증

`final.csv.gz`에서 `upset_B=1`은 3,999건이지만, 그중 `win=1`은 790건이다. 또한 해당 행의 실제 착순은 대부분 1~3위로 나타난다. 따라서 현재 라벨은 문서의 “1착”보다 **비인기마의 3위 이내 입상**에 가깝다. 라벨 생성 코드를 복원하여 정확한 규칙을 확정해야 한다.

### P0. `upset` 열의 자료형·코드 설명

`final.csv.gz`의 `upset`은 이진 열이 아니다. 실제로는 `0=일반`, `1=upset_A`, `2=upset_B`로 동작하며, 각 빈도는 48,552건, 4,097건, 3,999건이다. 문서에 코드북을 명시하고 노트북에서 새로 만든 이진 `upset`과 이름을 구분해야 한다.

### P1. 노트북 재현성 복구

- `cohens_d()` 함수가 노트북에 정의되거나 import되지 않아 첫 실행부터는 재현할 수 없다.
- 데이터 경로 `10th-toy-team3/final.csv.gz`가 특정 실행 위치에 의존한다. 노트북 기준 상대 경로로 고정해야 한다.
- 인기마 붕괴 분석은 제거 열을 만든 후에도 `bust_df = df[...]`로 원본 테이블을 사용한다. 그 결과 제거했던 시장 열 `is_fav`가 최상위 효과크기에 다시 포함됐다.
- 여러 숫자형 열에 결측치가 있으나 Cohen's d의 결측치 처리 방식이 명시되지 않았다.
- 마지막 셀은 두 표를 나란히 표시하려고 했지만 Jupyter의 마지막 표현식만 출력되어 인기마 붕괴 표만 보인다.

### P1. 모델 보고서의 평가 방식 보강

- `v3_report.html`은 학습·검증·테스트 구간, 피처 제거 목록, 라벨 생성 코드를 포함하지 않는다.
- 평균 배당 24.5배와 평균 적중률 23.8%를 단순 곱해 기대 회수를 계산하면 개별 말의 배당과 적중 간 관계가 사라진다. 개별 베팅 단위로 수익률을 다시 계산해야 한다.
- ROC-AUC와 Lift에 더해 PR-AUC, 신뢰구간, 시간순 외부 검증, 경주 단위 부트스트랩을 함께 보고해야 한다.

현재 파일을 즉시 이동하면 링크와 상대 경로가 깨질 수 있으므로, 먼저 정의와 실행 코드를 확정한 후 구조를 적용한다.
